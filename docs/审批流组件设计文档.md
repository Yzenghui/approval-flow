# 状态图

```text
[草稿] -- 提交 --> [审批中]
                     |
                     |-------------------> [通过]
                     |
                     |-------------------> [驳回] -- 修改重提 --> [审批中]
                     |
                     '-------------------> [撤回] -- 修改重提 --> [审批中]
```

**规则**：

- 草稿 → 审批中：发起人提交。
- 审批中 → 通过：所有审批节点都通过，流程结束。
- 审批中 → 驳回：任一节点驳回，流程终止，状态变更为“驳回”。
- 审批中 → 撤回：发起人在审批完成前撤回，流程终止，状态变更为“撤回”。
- 驳回 → 审批中：发起人修改后重新提交（修改重提），状态由“驳回”变更为“审批中”，流程从第一个节点重新开始。
- 撤回 → 审批中：发起人基于撤回的记录再次发起（修改重提），状态由“撤回”变更为“审批中”，流程从第一个节点重新开始。

# 需求文档

## 项目名称

审批流组件。



------

## 项目说明

轻量级审批流组件，可嵌入其他业务系统，提供完整的审批流程管理能力。核心后端接口可独立使用，演示系统基于 Vue 3 + Element Plus 实现，展示完整审批流程。

**核心功能**：

* 流程定义：一个流程由多个审批节点按顺序组成，每个节点可以设置生效条件，条件满足才执行该节点，否则跳过。
* 审批人指派：支持指定用户、角色、相对关系（如直属上级）三种审批人分配策略。
* 流程流转：按节点顺序逐个执行，当前节点审批通过后，系统自动找下一个需要执行的节点，直到没有节点可执行为止。
* 完整状态机：支持提交、通过、驳回、撤回、修改重提全链路操作 
* 审批记录：完整记录每一步操作日志，支持全流程轨迹追溯

#### 登录

**1. 功能描述**

用户通过用户名和密码登录系统，验证成功后返回访问令牌（Token）以及用户信息（去除密码），后续请求携带 Token 进行身份认证。

**2. 接口定义**

| 项目         | 说明                   |
| :----------- | :--------------------- |
| **接口路径** | `POST /api/auth/login` |
| **参数位置** | Request Body（JSON）   |
| **是否认证** | 否                     |

**请求参数**：

```json
{
  "username": "string",   // 用户名，必填
  "password": "string"    // 密码，必填
}
```

**响应示例**（成功）：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "xxxxxxxxxxxxx",
    "userInfo": {
      "id": 1,
      "username": "admin",
      "name": "管理员",
      "email": "admin@example.com",
      "roleCode": "ADMIN",
      "roleName": "管理员",
      "managerId": null,
      "status": 1,
      "createTime": "2026-04-01 10:00:00",
      "updateTime": "2026-04-06 15:30:00"
    }
  }
}
```

**响应示例**（失败）：

```json
{
  "code": 400,
  "message": "用户名或密码错误",
  "data": null
}
```

**3. 业务规则**

- 用户名不存在或密码错误 → 返回"用户名或密码错误"，并记录失败次数
- 使用 Redis 固定窗口计数器实现登录防暴力破解：
  - Key：`login:fail:{username}`，按用户名维度限流
  - 每次失败 INCR 计数，首次失败时设 5 分钟过期
  - 连续失败 5 次后，账号锁定 5 分钟
  - 登录成功后立即清除失败计数
- 用户状态为禁用（`status = 0`）→ 返回"账号已被禁用"
- 登录成功后，生成 Token，有效期 24 小时
- Token 通过响应体返回，后续请求放在 `Authorization: <token>` 头中

**4. 涉及数据表**

- `user`、`role`：验证登录并获取用户信息和角色信息
- Redis：登录失败计数 `login:fail:{username}`

**5. 异常情况**

| 异常                           | 返回码 | 提示信息                                 |
| :----------------------------- | :----- | :--------------------------------------- |
| 参数缺失                       | 400    | 用户名和密码不能为空                     |
| 用户名或密码错误（有剩余机会） | 400    | 用户名或密码错误，您还有 N 次尝试机会   |
| 账号已锁定                     | 400    | 账号已锁定，请5分钟后重试                 |
| 账号已禁用                     | 403    | 账号已被禁用，请联系管理员               |
| 系统内部错误                   | 500    | 系统内部错误，请稍后重试                 |

#### 注册

**1. 功能描述**

用户通过用户名、密码、真实姓名、邮箱注册账号，注册成功后默认分配员工角色（STAFF），账号状态为启用。

**2. 接口定义**

| 项目         | 说明                      |
| ------------ | ------------------------- |
| **接口路径** | `POST /api/auth/register` |
| **参数位置** | Request Body（JSON）      |
| **是否认证** | 否                        |

**请求参数**：

```json
{
  "username": "string",   // 用户名，必填，长度4-20位，字母开头，允许字母数字下划线
  "password": "string",   // 密码，必填，长度6-20位，必须同时包含字母和数字
  "name": "string",       // 真实姓名，必填，长度2-20位
  "email": "string"       // 邮箱，必填，符合邮箱格式
}
```

**响应示例**（成功）：
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": 1,
    "username": "zhangsan",
    "name": "张三"
  }
}
```

**响应示例**（失败）：
```json
{
  "code": 400,
  "message": "用户名已存在",
  "data": null
}
```

**3. 业务规则**

- 用户名必须唯一，已存在时返回“用户名已存在”
- 邮箱必须唯一，已存在时返回“邮箱已存在”
- 密码存入数据库前必须加密（BCrypt）
- 注册成功后默认分配角色：`role_id = STAFF角色对应的ID`
- 账号状态默认为启用（`status = 1`）
- 用户名和密码需符合格式要求，前后端均进行校验，后端不通过时返回相应提示。

**4. 涉及数据表**

- `user`：插入新用户记录
- `role`：查询 STAFF 角色的 ID

**5. 异常情况**

| 异常               | 返回码 | 提示信息                                   |
| ------------------ | ------ | ------------------------------------------ |
| 参数缺失或格式错误 | 400    | 对应的参数错误提示（如“用户名格式不正确”） |
| 用户名已存在       | 400    | 用户名已存在                               |
| 邮箱已存在         | 400    | 邮箱已存在                                 |
| 系统内部错误       | 500    | 系统内部错误，请稍后重试                   |

#### 通过

**1. 功能描述**

审批人通过当前任务，流程推进到下一个节点。如果没有下一个节点，流程结束。

**2. 接口定义**

| 项目         | 说明                                    |
| ------------ | --------------------------------------- |
| **接口路径** | `POST /api/user/tasks/{taskId}/approve` |
| **参数位置** | Path Variable + Request Body（JSON）    |
| **是否认证** | 是（需要登录）                          |

**路径参数**：

| 参数     | 类型 | 必填 | 说明   |
| -------- | ---- | ---- | ------ |
| `taskId` | Long | 是   | 任务ID |

**请求参数**：

```json
{
  "remark": "同意"
}
```

| 参数     | 类型   | 必填 | 说明             |
| -------- | ------ | ---- | ---------------- |
| `remark` | String | 否   | 审批意见，可为空 |

**响应示例**（成功）：

```json
{
  "code": 200,
  "message": "成功",
  "data": null
}
```

**3. 业务规则**

- 任务必须存在且状态为待处理（`status = 0`），否则返回“任务不存在或已处理”
- 只能处理自己的任务（`assignee_id` = 当前用户），否则返回"无权处理此任务"
- 使用 Redis 分布式锁防止并发重复提交：
  - 以 `task:lock:{taskId}` 为 key，使用 SETNX + 15秒过期时间获取锁
  - 获取锁失败时直接返回"任务正在处理中，请勿重复提交"
  - 使用 UUID 作为锁的 value，释放时通过 Lua 脚本原子校验 value 后删除，防止误删他人锁
- 数据库层幂等保障：UPDATE 语句带 `status = 0` 条件，若影响行数为 0 则返回"任务正在处理中，请勿重复提交"
- 使用事务：任务状态更新 + 审批记录 + 下一节点任务生成 + 实例状态更新必须同时成功或同时失败
- 通过后：
  - 当前 `task.status` 从 0 → 1（已处理）
  - 记录 `approval_record`（`action = 1` 通过，`task_id` 关联）
  - 查找下一个满足条件的节点（节点列表通过 Redis cache-aside 读取 `process:nodes:by-def:{definitionId}`，未命中回源 DB）：
    - 有下一节点：生成新 `task`（`status = 0`），`instance.status` 保持 1（审批中）
    - 无下一节点：`instance.status` 从 1 → 2（通过），流程结束

**4. 涉及数据表**

- `task`：更新当前任务状态，插入新任务（如有下一节点）
- `process_instance`：更新状态（如流程结束）
- `process_node`：查询下一个节点（优先 Redis 缓存）
- `process_definition`：查询流程定义（用于条件表达式）
- `approval_record`：插入审批记录
- Redis：分布式锁 `task:lock:{taskId}` + 节点列表缓存 `process:nodes:by-def:{definitionId}`

**5. 异常情况**

| 异常                       | 返回码 | 提示信息                     |
| -------------------------- | ------ | ---------------------------- |
| 参数格式错误               | 400    | 对应的参数错误提示           |
| 任务不存在或已处理         | 400    | 任务不存在或已处理           |
| 无权处理                   | 403    | 无权处理此任务               |
| 任务正在处理中（锁获取失败） | 400    | 任务正在处理中，请勿重复提交 |
| 任务正在处理中（影响行数0） | 400    | 任务正在处理中，请勿重复提交 |
| 审批人无法确定（下一节点） | 400    | 节点【节点名】审批人无法确定 |
| 未登录                     | 401    | 未登录或登录已过期           |

#### 驳回

**1. 功能描述**

审批人驳回当前任务，流程终止，并向流程发起人发出驳回通知。

**2. 接口定义**

| 项目         | 说明                                   |
| ------------ | -------------------------------------- |
| **接口路径** | `POST /api/user/tasks/{taskId}/reject` |
| **参数位置** | Path Variable + Request Body（JSON）   |
| **是否认证** | 是（需要登录）                         |

**路径参数**：

| 参数     | 类型 | 必填 | 说明   |
| -------- | ---- | ---- | ------ |
| `taskId` | Long | 是   | 任务ID |

**请求参数**：

```json
{
  "remark": "不同意"
}
```

| 参数     | 类型   | 必填 | 说明             |
| -------- | ------ | ---- | ---------------- |
| `remark` | String | 否   | 驳回意见，可为空 |

**响应示例**（成功）：

```json
{
  "code": 200,
  "message": "成功",
  "data": null
}
```

**3. 业务规则**

- 任务必须存在且状态为待处理（`status = 0`），否则返回“任务不存在或已处理”
- 只能处理自己的任务（`assignee_id` = 当前用户），否则返回"无权处理此任务"
- 使用 Redis 分布式锁防止并发重复提交：
  - 以 `task:lock:{taskId}` 为 key，使用 SETNX + 15秒过期时间获取锁
  - 获取锁失败时直接返回"任务正在处理中，请勿重复提交"
  - 使用 UUID 作为锁的 value，释放时通过 Lua 脚本原子校验 value 后删除，防止误删他人锁
- 数据库层幂等保障：UPDATE 语句带 `status = 0` 条件，若影响行数为 0 则返回"任务正在处理中，请勿重复提交"
- 使用事务：任务状态更新 + 实例状态更新 + 审批记录必须同时成功或同时失败
- 驳回后：
  - 当前 `task.status` 从 0 → 1（已处理）
  - `process_instance.status` 从 1 → 3（驳回）
  - 记录 `approval_record`（`action = 2` 驳回，`task_id` 关联）
- 事务提交后投递驳回通知（事务内只登记事件，不直接发消息）：
  - 事务内通过 `publishEvent` 登记事件，投递动作绑定在 `AFTER_COMMIT` 阶段，确保事务回滚时通知不会发出
  - 收件人为流程发起人（`recipient_id` = `process_instance.initiator_id`），内容为“您的【流程名】申请已被驳回，审批意见：xxx”
  - 投递至 `approval-event` 主题，消息体携带 `instanceId`、`taskId`、`type = 0`（驳回）、`recipientId`、`content`，并以 `taskId` 作为消息 Key，便于按业务主键检索
  - 消费端按 `uk_task_type(task_id, type)` 幂等落库：重复消息撞唯一键后忽略；落库失败返回重试，超过 `max-reconsume-times` 后进入死信队列
  - 通知属于附属能力，投递失败只记录日志，不回滚已提交的审批结果

**4. 涉及数据表**

- `task`：更新任务状态
- `process_instance`：更新实例状态
- `approval_record`：插入驳回记录
- `notification`：消费端异步落库驳回通知（按 `task_id` + `type` 幂等）
- Redis：分布式锁 `task:lock:{taskId}`
- RocketMQ：投递 `approval-event` 主题（`type = 0` 驳回）

**5. 异常情况**

| 异常               | 返回码 | 提示信息                 |
| ------------------ | ------ | ------------------------ |
| 参数格式错误       | 400    | 对应的参数错误提示       |
| 任务不存在或已处理 | 400    | 任务不存在或已处理       |
| 无权处理           | 403    | 无权处理此任务           |
| 任务正在处理中（锁获取失败） | 400    | 任务正在处理中，请勿重复提交 |
| 任务正在处理中（影响行数0） | 400    | 任务正在处理中，请勿重复提交 |
| 未登录             | 401    | 未登录或登录已过期       |
| 系统内部错误       | 500    | 系统内部错误，请稍后重试 |

#### 已办列表

**1. 功能描述**

审批人查看自己已处理的任务列表（通过/驳回），支持分页。

**2. 接口定义**

| 项目         | 说明                            |
| ------------ | ------------------------------- |
| **接口路径** | `GET /api/user/tasks/completed` |
| **参数位置** | Query String                    |
| **是否认证** | 是（需要登录）                  |

**请求参数**：

| 参数       | 类型    | 必填 | 说明                        |
| ---------- | ------- | ---- | --------------------------- |
| `pageNum`  | Integer | 否   | 页码，默认 1                |
| `pageSize` | Integer | 否   | 每页条数，默认 10，最大 100 |

**响应示例**（成功）：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "total": 5,
    "records": [
      {
        "taskId": 1002,
        "instanceId": 124,
        "definitionName": "员工请假流程",
        "nodeName": "主管审批",
        "initiatorName": "张三",
        "formData": "{\"days\": 3, \"reason\": \"感冒\"}",
        "action": 1,
        "createTime": "2026-04-24 10:00:00",
        "completeTime": "2026-04-25 14:00:00"
      }
    ]
  }
}
```

**3. 业务规则**

- 只返回当前用户已处理的任务（`task.assignee_id` = 当前用户，`task.status` = 1）
- 按任务完成时间（`update_time`）降序排列
- `action`：1通过 / 2驳回
- 分页参数校验：`pageNum` 小于 1 时默认 1，`pageSize` 小于 1 时默认 10、大于 100 时限制为 100

**4. 涉及数据表**

- `task`：查询已办任务
- `process_instance`：获取申请基本信息
- `user`：获取申请人姓名

**5. 异常情况**

| 异常         | 返回码 | 提示信息                 |
| ------------ | ------ | ------------------------ |
| 参数格式错误 | 400    | 对应的参数错误提示       |
| 未登录       | 401    | 未登录或登录已过期       |
| 系统内部错误 | 500    | 系统内部错误，请稍后重试 |
